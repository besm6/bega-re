# Новая дебютная база КАЛАХ

Историческая база утрачена. `tools/kalah_book.py` создаёт новую базу,
совместимую с неизменённым образом КАЛАХ из `2148:1230–1235`.
Сборщик автоматически помещает её в локальную зону `40:0153`.
Оригинальный код программы и её литералы не меняются.

Восьмеричные адреса ниже выделены как адреса; индексы дерева, размеры,
счётчики, номера лунок и глубины поиска приведены в десятичной записи.

## Генерация

```sh
make kalah-book
python3 tools/generate-kalah-book.py --depth 4 --output /tmp/opening.bin
python3 tools/check-kalah-book.py build/bega/volumes/2068
```

Отдельный генератор сохраняет 1024 слова по восемь байтов little-endian
с тегами данных и соседний JSON с параметрами, хешем и начальными оценками.
Это страница данных, а не полный дисковый том. Для нового тома:

```sh
python3 tools/build-bega-volumes.py --book-depth 4 --output /tmp/kalah/volumes
BEGA_VOLUMES=/tmp/kalah/volumes ./run-bega.sh
```

Генератор требует только Python 3; глубина по умолчанию — четыре
отдельных хода, включая дополнительные ходы в калах. Поиск использует
negamax, alpha-beta и таблицу транспозиций. В конечной позиции оценивается
разность итоговых камней; в промежуточной — камни в калахах с весом 100,
разность подвижных камней и разность возможностей немедленного
дополнительного хода с весом 8. Сохраняются все ходы с максимальной оценкой.
Начальное продолжение при этой глубине — `1,6`.

Это ограниченный поиск с явно заданной оценкой, а не доказательство
оптимальной игры. Результат детерминирован; случайный выбор между
рекомендованными ходами выполняет сама историческая программа.
База содержит рекомендации для **всех 6548 достижимых историй**, которые
помещаются в её диапазон индексов, включая произвольные допустимые ходы
человека. Поиск для каждой рекомендации продолжается за границу
сохраняемого дебютного дерева.

## Формат страницы

Формат следует из `consultOpeningBook` (`05104`) и `selAIMove` (`05241`)
в восстановленном `kalah.pas` и соответствующих команд исходного образа.
Числа 8415, 1547 и 224 подтверждаются его целыми литералами.

История начинается с индекса `i = 0`. После **каждого** отдельного хода
из лунки `m` индекс обновляется как `i = 6*i + m`.
При `i > 8415` программа выходит из дебютной базы. Таким образом, база
хранит истории до пяти ходов включительно, причём пятый слой ограничен
максимальным индексом. Дополнительный ход в калах тоже удлиняет историю.

Для индекса в пределах базы:

```text
j = i, если i <= 1547; иначе j = i - 224
номер слова = j // 8
сдвиг вправо = 6 * (7 - j % 8)
маска = (слово >> сдвиг) & 63
```

Шесть битов маски обозначают лунки: старший бит — лунка 1, младший —
лунка 6. Нулевая маска в достигнутой игровой позиции вызывает
`"ЧП" ДЕБЮТОВ`; рекомендация пустой лунки — отдельную ошибку.
Каждое слово содержит восемь масок. В слове **35** (адрес `0043`)
обязательна ГОСТ-сигнатура `!ДЕБЮТ`. Истории, соответствующие этому слову,
недостижимы. Сдвиг на 224 уплотняет дерево; полный перебор допустимых
ходов проверяет отсутствие наложения его достижимых записей.

Дерево симметрично по сторонам: нумерация лунок всегда относится к игроку,
который ходит. Генератор реализует раскладывание против часовой стрелки,
пропуск чужого калаха, дополнительный ход и захват из противоположной
лунки согласно `exMvLogic`. Рекомендуемую последовательность дополнительных
ходов оригинал дополнительно просматривает через `consultOpeningBook`.

## Выход из дебюта и проверка

Для категорий У и Э после исчерпания дерева включается собственный поиск
КАЛАХ и проверка корректирующих продолжений. Поэтому в `66:0635` создаётся
пустая база: слово 0 — `!СОRR!`, слово 1 — последний занятый индекс 1,
записей со слова 2 нет. Категории Ю и К дебютную базу не используют.

`check-kalah-book.py` перебирает все допустимые истории на независимом
представлении из 16 слов, соответствующем исходному `Position`.
Проверяются сохранение 72 камней, уникальность размещения масок,
сигнатура и допустимость каждого рекомендуемого хода.
`make check-bega` дополнительно запускает сам оригинал: проверяет первые
ходы ДЖИНа `1,6`, получившееся поле, чтение `40:0153` и последующее
чтение `66:0635` после выхода из дебюта. Параметры и SHA-256 новой базы
сохраняются в `provenance.json` рядом с происхождением оригинальных образов.
