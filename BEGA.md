# Запуск оригинального игрового блока БЕГА

Номера зон и машинные адреса здесь восьмеричные, номера томов десятичные.

## Образ и исходник

В проверенных `/usr/local/share/besm6/2148` и `/usr/local/share/besm6/2248`
БЕГА расположена в зонах `1125–1131`. Все пять зон данных побитово
одинаковы на обоих томах и совпадают с репозиторным `bega.o`.
SHA-256 выгрузки из 30 720 байт, по шесть байтов на слово:

```text
ca3240e2a12b7ad7e3bf7a56fe80f8cdc8df80b0be58bc40e690e2689662374e
```

В заголовке находятся имя `БЕГА`, дата `200183` (20.01.83), сигнатура
`РАSСАL`, начало рабочего кадра `11346` в слове `00005` и число зон `5`
в слове `00006`. Дата заголовка не устанавливает версию компилятора.
Вход `00007` вызывает АДСИС `74003`; в `00010` расположен переход
в главную программу `11100`. Литералы начинаются с `00011`, код — с
`02642`, последняя служебная инициализация — с `11341`; конец сохраняемой программы
и литералов — перед `11346`. Сравнение пяти зон включает также остаток
до `11777`, который не следует считать исполняемым кодом.

Связь с `bega.pas` подтверждается строками, таблицей диспетчера и входами
процедур. Исходник заново не компилировался; точность его реконструкции
целиком этой работой не устанавливается. Например, числовые литералы
с суффиксом `C` в исходном декомпиляторском представлении требуют
проверки основания по машинным словам.

| Вход | Назначение |
|---|---|
| `02650` | `TTIN`, ввод игровой команды |
| `02753` | Проверка оставшегося времени |
| `03176` | Чтение зоны через резидент `77451` |
| `03233` | Проверка прав и расписания игры |
| `03370` | Разбор команды через `77400` |
| `03420` | Опрос состояния терминального обмена |
| `03442` | Передача массива графического вывода через Э71 |
| `03475` | `landMsg`, сообщения посадки |
| `04140` | Вложенная `getval`, ввод расхода и команд посадки |
| `04323` | Основное тело посадки на Луну |
| `04751` | Разметка для крестиков |
| `07402` | Основное тело французских шашек |
| `10230` | Основное тело скачек |
| `10640` | Обёртка выхода через `76022` |

Существующими инструментами можно получить выгрузку и листинг:

```sh
besmtool dump 2148 --start=01125 --length=5 --to-file=build/bega-original/bega.bin
dtran -n -f 02642 -E entry.txt bega.o > build/bega-original/bega.asm
```

`besmtool` выбирает том по своему пути поиска. Сборщик читает точный
путь `--source` и записывает его в отчёт происхождения.

## Локальный том

`tools/build-bega-volumes.py` по умолчанию использует исходный 2148 и
создаёт `build/bega/volumes/2068`. Исходный том не изменяется.
Рабочее окружение берётся именно с 2148: совпадение БЕГА на 2248
не означает совпадения резидентов этих томов.

| Источник 2148 | Зона 2068 | Назначение |
|---|---|---|
| `1000` | `0000` | Каталог и служебный код ПУЛЬТа |
| `1005–1006` | `0005–0006` | ДАЙ и АДСИС |
| `1035–1037` | `0035–0037` | СБОЙ, ЗГЛВК и КТЛБИБ |
| `1040–1041` | `0040–0041` | ПУСК и НАБЛ |
| `1051` | `0051` | БАВТ |
| Новый код | `0100–0103` | Архив ИГРА, запускалка, монитор и команда |
| `0064` | `0104` | Резидент ДЖИН |
| `1125–1131` | `0125–0131` | Пять неизменённых зон БЕГА |
| `1137` | `0137` | Неизменённая таблица позиций шашек |
| `1230–1235` | `0230–0235` | Шесть неизменённых зон КАЛАХ |
| `1236–1237` | `0236–0237` | Две неизменённые зоны ШККАЛ: справка и турнир |
| Новые данные | `0153` | Сгенерированная дебютная база КАЛАХ |
| Новые данные | `0635` | Пустая база коррекций с сигнатурой `!СОRR!` |
| Новые данные | `1013` | Учёт игроков и статистика КАЛАХ |

В минимальном каталоге оставлены подключённые службы и запуск ИГРА.
В локальном СБОЙ слово `0035:0012` изменено с `0010010000402667`
на `0010010000400037`, чтобы указывать на перенесённый список архивов.
Все изменения каталога и этот дескриптор фиксируются в `provenance.json`.

Шашки в `07402` выполняют `readZone(0,400137)` и читают
**устройство 40, зону 0137**, в буфер `64000`.
В начале зоны находятся 65 отсортированных записей выбора ходов белых;
вторая таблица начинается с `64101`, содержит 698 основных записей
и цепочки хеширования. `PickWhite` ищет позицию двоичным поиском,
`PickBlack` — через хеш-таблицу. Изменение отметок повторения позиций
происходит в оперативной памяти. Записи этой зоны на диск игра не делает.

Скачкам, посадке и разметке поля дополнительные зоны данных не нужны.
Игровой паспорт подключает локальный 2068 на устройстве `40` без записи
и на устройстве `66` с записью. Оба номера обозначают один физический
локальный файл: КАЛАХ читает программу и дебюты через 40, учёт игроков —
через 66. Даже тренировка обновляет статистику в `66:1013`.
Том 2099 используется эмулятором как системный.

Для отдельной копии:

```sh
python3 tools/build-bega-volumes.py --source /path/to/2148 --output /tmp/bega/volumes
BEGA_VOLUMES=/tmp/bega/volumes ./run-bega.sh
```

Сборщик отказывается перезаписывать существующие файлы. Исключение —
`--upgrade` для прежнего комплекта без КАЛАХ: проверяется исходный SHA-256
тома, старые файлы сохраняются в `pre-kalah/`. Запускалка выполняет такое
обновление автоматически. Изменённый старый том требует нового `--output`.
`bega.bin` содержит исходные пять зон по шесть байтов на слово.
`provenance.json` содержит SHA-256 исходного тома, сырых слов с тегами
для каждого перенесённого участка, выгрузки и итогового тома.
Дополнительно сохраняются `kalah.bin` и `school.bin`; их SHA-256:

```text
КАЛАХ  f19ec5de2c09df28818bab091688f6e12bb62901b957f06f54da52ed41b78472
ШККАЛ  3e41b19556c023d4374be96294f894a5c4c312fdc8236e5cdf63b2792f1a3a8b
```

Контрольный SHA-256 итогового тома относится к моменту сборки: после игры
зона `1013` меняется. Программные зоны остаются исходными.

## Монитор и терминал

Используется общий с БИБЛ модуль `tools/monitor.py` с параметрами БЕГА.
Монитор загружается в `60000–61777`, командная область — `62000–63777`.
Он загружает резидент ДЖИН в `76000`, устанавливает входы `76021/76022`
и признак `ТАМБОВ` по `76233`, загружает АДСИС в `74000`
и пять зон программы в `00000–11777`.

Вход передаёт 62 слова контекста начиная с `gl22z`, подготавливает
командный TEXT, выполняет RESET и сохраняет его дескриптор в `76253`.
Учебный пользователь получает право SET `[3]` в `gl23z`, то есть
маску `1 << 44`. Поэтому зона расписания `66:1005` не требуется.
При входе с `КАЛ ТРЕН …` монитор устанавливает SET системных признаков
`[27]`, разрешающий выбор категории и начинающей стороны. При входе с
обычным `КАЛ` этот признак снимается: в оригинале он закрывает турнирную
игру. Режим сохраняется до выхода из оверлея; для смены режима вернитесь
в БЕГА через `КОН`. Бюджет времени находится в `gl30z`.

Посадка явно задаёт `М7 = 71000` в правой половине `04131` и выводит
накопленный текст через Э71 в `04132`. Загруженная АДСИС по умолчанию
начинает OUTPUT с `72000`. Монитор устанавливает `75205` и `75224`
в `71000`, согласуя начальный и текущий указатели OUTPUT с программой.
При этом код БЕГА и АДСИС в памяти и их дисковые копии не исправляются.

Шашки и скачки передают графику непосредственно через Э71.
В обычном режиме DISPAK переводит перемещения курсора в ANSI;
в curses-консоли `-V` их принимает эмуляция терминала. Проверка использует
обычный режим и сохраняет исходный поток с управляющими последовательностями.

Вход `76022` принимает переходы `6400230` (КАЛАХ) и `2400236` (ШККАЛ).
При переходах сохраняются все 62 слова контекста и командный TEXT.
ШККАЛ возвращается в КАЛАХ дескриптором `3400230`; монитор загружает
все шесть зон, нормализуя число страниц по расположению образа.
Возврат `1660730` из дочернего блока загружает БЕГА; дочерний `КОН`
заменяется на `ИГР`, чтобы получить игровой запрос. Остальные команды,
например `ШКО ИНФ`, передаются дальше. `КОН` из самой БЕГА восстанавливает
резидент ПУЛЬТа из барабана 27.
ЛОТО, ГЛИССАДА, КУБ и ИНСПЕКТОР пока не подключены; их переходы
возвращают в ПУЛЬТ.

Дебютная база создана заново, подробнее — [KALAH-BOOK.md](KALAH-BOOK.md).
Категории У и Э используют её, затем собственный поиск и пустую базу
коррекций; категории Ю и К обходятся собственным поиском.
Локальная запись `501300` изначально не имеет результатов и отложенных
партий. Исходные чужие записи не копируются.

Дневной лимит оригинала применяется и к тренировке. За тренировку
счётчик увеличивается на два, с насыщением до пяти; после трёх тренировок
следующий запуск отклоняется сообщением `СЕГОДНЯ ИГРАТЬ БОЛЬШЕ НЕ БУДУ`.
Для независимых примеров можно собрать другой каталог томов через
`--output`, сохранив прежние результаты.

## Проверка

`make check-bega` запускает двенадцать файлов из `sessions/bega/`:
справку, русский аварийный полёт, английский полёт с идеальной посадкой,
шашки за обе стороны, полный забег и разметку поля.
Проверяются характерные сообщения и числовые результаты посадки,
в том числе `PERFECT LANDING`, касание на 149-й секунде, округлённая
скорость 3 фут/с и остаток 576 фунтов топлива в английском примере,
допустимый ход белых и ответ компьютера, сдача и завершение партии,
окончание забега, графический вывод, завершение ПУЛЬТа. Для КАЛАХ
проверяются полная справка с тремя остановками `ИДТИ?`, переход из ШККАЛ
в БЕГА, тренировки Ю/У/Э, первые два дебютных хода ДЖИНа `1,6`,
перерисованная позиция и переход от дебютов к поиску с чтением коррекций.
На отдельной копии проверяется обычный `КАЛ`: ход человека, ответ
компьютера, просьба сдаться и запись результата либо отложенной партии.
Результат скачек и конкретный ответ шашечной программы не фиксируются:
они зависят от начального состояния генераторов.

Для сетки проверены пятнадцать печатных строк по 26 точек, затем ещё
одна строка через прямой терминальный вывод. Эти размеры следуют из
машинных границ циклов `017` и `014`, а не из прочтения этих чисел
как десятичных. Компьютерных ходов в режиме КРЕСТИКИ нет.

По трассам Э70 проверяются загрузки всех пяти зон БЕГА, резидента,
АДСИС и таблицы шашек. Сверяются исходные слова и теги всех перенесённых
программ, сохранившиеся части ПУЛЬТа, равенство выгрузки `bega.o`.
Все сеансы работают на временной копии с новым учётом игроков.
Между тренировками сохраняется статистика: проверяются приращения
счётчиков категорий Ю/У/Э и изменение только зоны `1013`.
SHA-256 исходного и постоянного локального томов до и после проверки
должны совпасть. Отдельно проверяются все 6548 достижимых дебютных
историй, отсутствие наложения записей и допустимость каждого
рекомендуемого хода. `make check` дополнительно проверяет библиотечный блок.

В `build/bega/logs/` сохраняются `.input`, `.out`, `.trace` каждого сеанса
и общий `check.json`. Это проверка запуска оригинального образа;
перекомпиляция `bega.pas`, полные выигрышные партии
и curses-режим в неё не входят.

## Решатель французских шашек

```sh
make solve-checkers
# либо
python3 tools/solve-checkers.py --output /tmp/checkers-solution.json
```

Решателю нужны только Python 3 и репозиторный `bega.o`. Граф из
`P6165` (`06165–06232`) и дополнительные правила `validate`
(`06233–06326`) сверены с дизассемблированием этого образа.
Скрипт проверяет SHA-256 `bega.o`, связывая заданный граф с проверенным
бинарником; заново команды не декодирует.

Полным перебором рассматриваются 2640 состояний: три неразличимые
белые фишки, одна чёрная и сторона, которая должна ходить.
Ретроградный анализ строит множество позиций с гарантированным
окружением чёрной. В нём белые выбирают переход с минимальным рангом,
чёрные — с максимальным. Убывание ранга проверяется для всех переходов
выигрышной стратегии. В остальных позициях чёрные могут достичь клетки 0
или избежать окружения до повторения позиции, которое означает их победу.

Из начального расположения белых `0,1,3` и чёрной `5` белые выигрывают
при обеих очередностях: не более чем за 23 отдельных хода при первом
ходе белых и за 28 при первом ходе чёрных. В первом случае кратчайшее
выигрышное начало — `0–2`; во втором наиболее упорный ответ — `5–2`.
Штатная программа всегда начинает белыми; второй вариант — отдельный
расчёт тех же правил с изменённой очередностью первого хода.

Отчёт `build/bega/checkers-solution.json` содержит результаты,
оценки всех первых ходов и пример линии оптимальной игры для каждой
очередности. Это теоретическое решение правил; оно не утверждает,
что встроенные таблицы компьютера всегда выбирают оптимальный ответ.
